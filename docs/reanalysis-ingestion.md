# 外部再分析数据接入（已确认阻塞，管线待命）

## 现状与阻塞（2026-11-15 结论：无坐标，暂不接入）

GEFCom2014 风电的十个 `ZONEID` 是**匿名站**：官方数据只有 `U10/V10/U100/V100` + 归一化功率，没有经纬度、容量或机组布局；其他复现项目也记录其 `latitude/longitude` 为空。因此外部再分析数据**无法按站取数**，必须先有 `ZONEID → 经纬度` 的映射。

## 已就绪的管线

| 组件 | 说明 |
|---|---|
| `configs/sites.json` | 十站坐标与 UTC 偏移的模板；任一坐标为空时脚本拒绝运行 |
| `scripts/fetch_reanalysis.py` | 按站拉取 NASA POWER 逐时数据（T2M、PS、WS10M、WD10M、WS50M），缓存原始 JSON，输出 `data/external/reanalysis_hourly.csv` |
| 校验 | 已用占位坐标做过端到端连通性测试（48 小时解析正常），占位数据已删除 |

NASA POWER 不需要 API key，社区参数 `RE`，时间戳为 UTC；本项目数据是**无时区源时钟**，所以 `configs/sites.json` 里必须填 `utc_offset_hours`，脚本会做平移。

## 填好坐标后怎么跑

```sh
# 1) 填 configs/sites.json 的十行 latitude / longitude / utc_offset_hours
uv run python scripts/fetch_reanalysis.py --dry-run          # 只校验配置
uv run python scripts/fetch_reanalysis.py --start 20120101 --end 20131231
```

## 下一轮实验的预注册草案（等数据到位再正式写）

- **新增特征**：`T2M`、`PS`、由二者算出的空气密度 `rho = PS/(287.05*(T2M+273.15))`、`WS50M`（更接近轮毂高度）、`WD10M` 的方向 sin/cos。
- **加在哪一层**：第二层分站模型的输入（与现有 `stage1_*`、跨站风场并列）。
- **机制**：功率与空气密度近似成正比，同风速下低温高压日发电更高；`WS50M` 补充轮毂高度风速。
- **数据使用**：训练 2012、早停与融合权重 2013 上半年、测试只评分；再分析数据本身不涉及标签，可全期使用。
- **判定**：验证集七日块配对区间上界 ≤ −0.0002 才允许开测试集。

## 风险

1. **坐标不可靠**：若坐标只是近似（例如只到州/区域级），再分析与实际站点的风速相关会明显下降，特征可能变成噪声——先用验证集单站相关性检查（相关系数 < 0.5 就应放弃）。
2. **时间基准**：若 `utc_offset_hours` 填错，特征整体错位 1–N 小时，效果会显著变差；这是接入时最容易犯的错。
3. **数据集匿名性**：若官方刻意匿名，外部数据接入只能算"近似替代"，论文里必须说明这是基于推定坐标的补充信息，而不是原始观测。
