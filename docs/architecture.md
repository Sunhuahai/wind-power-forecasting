# 数据流与扩展边界

原始官方 ZIP → Task 15 CSV 解包 → 逐字段质量标记 → PostgreSQL 幂等写入 → 按站点查询 → 统一特征 → 固定时间划分 → 训练/验证 → 保存模型 → 测试期逐日回放 → PostgreSQL 预测 → CSV/图表/报告。

`build()` 在数据库查询后，对每个目标时刻建立所属日的 00:00 起点；目标 00:00 属于前一日。历史索引以精确时间查找，并只查询起点前 1–24 小时，缺小时不会使 lag 按行偏移。构造特征不读取目标标签；随后才关联标签并筛选完整预测日。训练与测试回放、独立起点预测使用同一个 `feature_row()`。

数据库原始时间为 timestamp without time zone，另存原始时间字符串；未知时区和发布时刻保持未知。当前 NWP 源每站每有效时间只有一个四分量向量，没有真实版本字段。本项目不声称拥有历史 as-of 版本仓库。生产接入必须引入真实预报发布时间、到达时间及观测可用延迟，并扩展唯一键和查询。

CSV 原始重复键直接报错，避免任意保留冲突数据。功率非法/缺失和非有限气象数据转 NULL 并保存 JSON 字段标记。清洗不补造业务数据。数据库时间连续性检查区别于字段完整性；完整时间轴也可能包含缺失功率。

测试期模型不更新。使用过去测试日期已经发生的功率是逐日起点业务所需；同日起点之后真实功率绝不进入特征。测试数据只用于固定配置模型的最终指标与图表，不根据指标再次修改超参数。

每站独立建模，避免无谓的场站编码和多站泄漏。未来可以增加跨场站模型、真实发布批次和企业功率单位，但需要明确的新迁移和独立评估，不能把本次归一化数据推测成 MW。
