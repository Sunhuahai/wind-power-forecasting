# 第一章　数据集与任务

## 1.1 数据集是什么

GEFCom2014（Global Energy Forecasting Competition 2014）是能源预测领域的公开竞赛，风电赛道（Wind Track）给出了 **10 个匿名风电场的两年小时级数据**。它的价值在于：真实、公开、带数值天气预报（NWP）预报、有统一的评分口径，适合做方法对比与复现；它的局限也来自"匿名"——没有坐标、没有装机容量、没有机组布局、没有限电记录。

本项目库内实测的覆盖范围：

| 项 | 值 |
|---|---|
| 时间范围 | 2012-01-01 00:00 ～ 2014-01-01 00:00 |
| 站点编号 | `ZONEID` 1–10（匿名） |
| 频率 | 小时级 |
| NWP 分量 | `U10`、`V10`、`U100`、`V100`（10 米/100 米风速的 u、v 分量） |
| 目标 | `TARGETVAR`，归一化功率，落库时约束在 0–1 |
| 行数 | 功率观测 175,440；NWP 预报 175,440（每站每小时一条） |

> 说明：竞赛原始数据的训练期与测试期划分与本项目不同。本项目为了做"可复现的离线优化"，把 2012 全年作为训练期、2013 上半年作为验证期、2013-07-01～2014-01-01 作为冻结测试期。这个划分从项目初期就固定，后续所有轮次不得改动。

## 1.2 任务定义

对每个预测起点 `origin`（每小时一个），模型要用**该起点可见的 NWP 预报**预测 `origin+1 … origin+24` 共 24 个目标时刻的十站功率。十站合并评价，即把 10 站 × 小时数拼成一个向量算 RMSE。

三个必须写清楚的细节：

1. **NWP 的"可见性"**：数据集只给了"每个有效时刻对应的预报"，没有给预报的实际发布/到达时刻。项目沿用竞赛回放假设（预报在起点可用），文档里反复标注了"NWP 实际发布时间未知"。这在真实生产里必须换成三时间轴（发布/到达/有效），否则回测会穿越。
2. **完整 24 小时窗口**：只保留 `origin` 下 24 个提前量齐全的样本，避免不同模型看到不同的样本集。
3. **功率归一化**：`TARGETVAR` 已归一到 0–1，模型输出裁剪到同一区间；没有额定容量，所以指标是"归一化 RMSE"，不能直接换算成 MW。

## 1.3 数据质量问题

| 问题 | 表现 | 对实验的影响 | 处理方式 |
|---|---|---|---|
| 缺测 | 少量小时没有观测 | 丢弃该目标时刻的标签 | 训练时剔除；评价时只算有标签的样本 |
| 静风与零出力 | 8.7% 的测试小时实际功率 < 0.005，其中 2,813 小时精确为 0 | 低功率段误差占 MSE 的 22.9% | 曾专门做两段式模型，未成立（7.4） |
| 匿名站 | 无坐标、无容量、无布局 | 无法接外部再分析数据、无法做尾流修正 | 只做站间统计量，不做物理建模 |
| 限电缺失 | 低功率可能是人为限电而非风小 | 模型会系统性高估 | 公开数据集无解；真实数据必须接入标记 |
| 归一化口径 | 每站归一化方式未公开 | 站间误差不可直接比较 | 只报合并指标，逐站只做相对比较 |

## 1.4 与真实生产的差距

这份记录的所有结论都建立在"公开数据的离线回放"上，接真实数据时要重新面对四件事：

1. **NWP 有版本**：同一有效时刻会有多批预报，必须按"到达时刻 ≤ 预测起点"选版本；
2. **观测有迟到与补录**：需要 `received_at`，否则回放会用到未来数据；
3. **有检修与限电**：低功率不一定代表风小，这是上线后最容易踩的坑；
4. **有容量与坐标**：可以算空气密度、尾流、功率曲线，这些在匿名数据上都做不了。

# 第二章　评估协议

## 2.1 为什么先把规则钉死

这条链跑到第 9 个节点时，测试集已经被用了 11 次。反复在同一个测试集上做选择，会产生两个后果：

1. **乐观偏差**：每次"试到更好"都是一次隐式选择，测试集逐渐变成第二个验证集；
2. **结论不可信**：区间虽然还在，但"这个数字代表泛化能力"的说法已经不成立。

所以协议不是形式主义，它决定了"哪些数字还能被当成证据"。

## 2.2 数据划分与允许用途

| 数据 | 时间范围 | 允许用途 | 禁止用途 |
|---|---|---|---|
| 训练集 | 2012-01-01～2012-12-31 | 训练所有模型、构造 OOF、拟合经验曲线 | — |
| 验证集 | 2013-01-01～2013-06-30 | 早停、选结构、拟合凸融合权重、验证集门禁 | **训练任何模型、重拟合** |
| 测试集 | 2013-07-01～2014-01-01 | 只评一次分（每个候选） | 调参、选结构、定权重 |

这条红线是项目中途确立的：早期有 3 个节点把验证期标签并进最终拟合，后来按用户要求全部作废（第八章）。

## 2.3 严格协议（2026-11-14 起）

```
训练：只用 2012 年的时间顺序 OOF（每站 6,576 小时，十站合并 65,760 行）
早停：2012 训练期内部再切 15% 留出（或 OOF 分折）
选结构：验证集
融合权重：验证集（43,008 小时），拟合后冻结、写文件
评分：测试集，只评一次
```

注意两个容易混淆的点：

- **"OOF"指的是第一层模型的样本外预测**。第二层的训练输入必须是第一层在 2012 期内、对"当时还没见过的时段"的预测，不能用同一时段真实标签。
- **验证集用于拟合融合权重是允许的**，因为权重只有几个标量；但把验证集标签拿去训练一个模型（哪怕叫 meta-learner）就越界了。

## 2.4 指标

| 指标 | 定义 | 用途 |
|---|---|---|
| RMSE | √(mean((ŷ−y)²))，十站合并 | 主指标，决定节点是否成立 |
| MAE | mean(|ŷ−y|) | 辅助指标；区间跨零时不单独声称改善 |
| 逐站 RMSE | 分站计算 | 诊断（是否只有少数站改善） |
| 分段 RMSE | 按提前量 1–8 / 9–16 / 17–24 | 诊断误差随提前量的结构 |

## 2.5 七日连续日历块配对 bootstrap

**为什么不用普通配对 t 检验**：小时级误差强自相关（相邻小时天气几乎一样），独立同分布假设不成立，会严重低估区间宽度。

**做法**：
1. 把测试期按"连续 7 天"切成块（十站共享同一批块）；
2. 每个块内同时取两个模型在该块上的误差；
3. 重采样块（有放回），计算配对 RMSE 差；
4. 重复 2,000 次，取 2.5% 与 97.5% 分位。

**为什么是 7 天**：一周能覆盖一次完整的天气过程与一次调度周期；块太短则相关性没消掉，太长则块数太少、区间不稳。

**判定**：区间不含零才算"有证据"；同时从 2026-11-14 起，**验证集区间上界必须 ≤ −0.0002** 才允许开测试集——这一条是纪律，因为测试集已经被反复使用。

## 2.6 开测试集的门槛（两次收紧）

| 时间 | 规则 | 原因 |
|---|---|---|
| 项目初期 | 验证集有改善就评测试集 | 常规做法 |
| 2026-11-14 中 | 验证集配对区间不含零才评 | 防止噪声当信号 |
| 2026-11-14 晚 | 验证集区间**上界 ≤ −0.0002** 才评 | 提前量分段那轮验证 −0.000444、上界 −0.000203 贴线，测试却是 −0.0000132，白烧一次 |

## 2.7 测试集使用台账

| 序号 | 用途 | 结果 |
|---:|---|---|
| 1–10 | 前 10 个节点的评分与诊断 | — |
| 11 | 提前量分段建模 | −0.0000132，区间跨零，不成立 |

从第 11 次之后，进入"能不碰就不碰"状态：后续 4 轮候选（一致性特征、滚动残差、8 种子、种子平均扩展）全部停在验证集门禁，没有开测试集。

## 2.8 数据使用声明

每个实验目录都有 `protocol.json`，显式写明五项：

```json
{
  "training_data": "2012 OOF only, 65,760 rows",
  "early_stopping": "15% holdout inside 2012 training window",
  "selection": "validation 2013 H1 (STL: structure choice only)",
  "blend_weights": "validation 2013 H1, 43,008 hours, frozen before test",
  "test_scoring": "frozen 2013 H2, scored once"
}
```

这是为了抽查：任何人打开目录就能判断"这轮有没有用验证集标签训练"。

## 2.9 作废规则

- 只要训练数据里出现 2013 年标签（哪怕只出现在最终重拟合），该节点作废，不进图、不进注册表、不与新节点比较；
- 作废节点的证据保留在 artifacts 目录里，供核对，不删除；
- 作废节点不得复活（第八章列的三个数字就是这种情况）。

# 第三章　基线与误差结构

## 3.1 早期五模型基线

项目最初搭了一套五模型对比（LightGBM / XGBoost / 随机森林 / 线性回归 / 持久化基线），用来确认"树模型明显优于线性与持久化"。这一阶段的价值是建立流水线（取数、特征、训练、预测回写、验收），不是产生最优指标。

## 3.2 冻结 C 基线：0.170454204

C 基线 = 只用基础特征集（原始 NWP 四分量 + 派生风速/风向/风切变/时间编码 + 提前量），LightGBM 训练，严格只用 2012 数据，验证集早停。它的指标：

| 指标 | 值 |
|---|---|
| RMSE | **0.170454204** |
| MAE | 0.123454374 |
| 测试小时 | 42,432 |

这是后续所有节点的比较起点。它同时是"物理实验"的对照组：物理残差学习把 MAE 降到 0.121856，但 RMSE 升到 0.170535（区间跨零），所以**不作为优化节点**。

## 3.3 kPower 两层复现：0.162180238

第二层结构来自公开复现（kPower 方案）：十站先各自预测，再把十站第一层预测作为第二层输入。它一次把 RMSE 降到 0.162180238（−4.85%），是整条链上最大的一步。

## 3.4 误差结构诊断

在动手加特征之前，先看清误差长什么样：

| 维度 | 观察 | 含义 |
|---|---|---|
| 提前量 | 1–8 小时 RMSE 0.128；9–16 小时 0.156；17–24 小时 0.149 | 误差随提前量上升，来自 NWP 本身衰减 |
| 站间 | 最好与最差站差约 0.03 | 站点难度差异明显，但合并指标仍以十站为主 |
| 功率段 | 低功率段（<0.005）误差占 MSE 的 22.9% | 静风边界难，但不是主要矛盾 |
| 时间 | 夏季与过渡季误差不同 | 与天气过程强度相关 |

这张诊断表直接决定了后面三步的方向：**先补空间信息（邻站/跨站）、再补样本量（共享模型）、最后压方差（多种子）**。

# 第四章　有效节点（逐个详解）

节点表共 9 行，第 1 行是基线，因此**实际改进是 8 步**，累计 −8.47%。每个节点都按"动机 → 做法 → 配置 → 权重 → 结果 → 区间 → 解读 → 代价"写，避免只留结论。

## 4.1 节点 2：天气邻域 + 时间顺序 OOF 跨站两层（−4.85%）

**动机**：十站独立建模时，每站只看到自己的 NWP；而风场在空间上是相关的——邻站"怎么吹"能补充本站预报的不足。

**做法**：
1. 第一层：每站用基础特征（C 集）训练 LightGBM；
2. **用时间顺序 OOF 生成第一层预测**：把 2012 切成连续时间块，每一块用"之前的数据"训练、对"当前块"预测，保证第二层看到的输入不含当前块标签；
3. 第二层：输入 = 本站 C 特征 + 同日风能邻域特征 + 十站第一层预测，再训练 LightGBM；
4. 验证集早停。

**为什么必须 OOF**：如果直接用第一层在同一批数据上的拟合值当第二层输入，第二层会学到"第一层在训练集上有多准"，而这个准度在测试期不存在——典型的 stacking 泄漏。

**结果**：

| 方案 | MAE | RMSE |
|---|---:|---:|
| C（同 OOF 时间段训练对照） | 0.124524877 | 0.171821377 |
| C + 天气邻域 | 0.119839461 | 0.167073932 |
| 完整两层（再加跨站预测） | 0.115982666 | **0.162180238** |

相对基线 0.170454204：**−4.8541%**；MAE 0.123454374 → 0.115982666（−6.05%）。十站中八站改善，Zone 2 与 Zone 8 变差。

**同样本消融**（三组用同一 OOF 时间段、同一超参、同一早停）：

| 比较 | RMSE 差 | 七日块配对 95% 区间 |
|---|---:|---|
| 邻域 vs C | −0.004747446 | [−0.006269744, −0.003219281] |
| 完整两层 vs 邻域 | −0.004893694 | [−0.006190094, −0.003657589] |

**解读**：两组特征在当前配对设计下都有贡献，且贡献量级相近。注意边界——这是"整体方案"的效果，不能推断到其他年份或任意学习器。

**代价**：训练量翻倍（十站 × 多层）；第一层 OOF 需要时间分块，块边界处理错就会泄漏。

## 4.2 节点 3：验证集全站共享凸融合（−0.39%）

**动机**：邻域模型与完整两层各有长处，简单选一个会丢掉差异；用验证集拟合一组合权重，能吃到"误差互补"。

**做法**：固定三个候选（C、邻域、完整两层），只在 43,008 个验证小时上最小化合并 MSE，约束权重非负且和为 1（凸组合），拟合后**先写文件冻结**，再加载测试集评分。

**权重**：C **0.122281198** / 邻域 **0.084286243** / 完整两层 **0.793432559**。

**结果**：0.162180238 → **0.161552864**（再降 0.3868%），相对最初基线累计 −5.22%。

**区间**：RMSE 差 −0.000627374，**[−0.000963197, −0.000286049]**；MAE 差 −0.000077924，区间 [−0.000326755, +0.000176262]**跨零**，所以不声称 MAE 改善。

**解读**：三个权重里最强的单模型占 79%，另两个合起来 21% 提供补充。这是"保留较弱但有差异的模型"的典型案例。

**代价**：权重由验证集拟合，存在乐观偏差；验证集同时被基模型用于早停，所以这个误差不是独立泛化误差。

## 4.3 节点 4：十站原始风场（−0.58%）

**动机**：第一层预测已经把原始风场"压缩"过一次，信息有损；把十站同一预报时刻的原始 100 米风矢量直接喂给第二层，可能补回被压掉的空间细节。

**做法**：在既有特征外追加十站的 `U100`、`V100`、100 米风速，共 **30 维**；按"预测起点 + 目标时刻"双键匹配；只读预报字段，不碰功率；训练样本仍是原来的 OOF 时间段（每站 6,576 小时）。

**权重**：上一最优 **0.546497836** / 新模型 **0.453502164**。

**结果**：新模型单独 RMSE 0.160960701；融合后 **0.160622327**（较上一节点再降 0.5760%）。

**区间**：RMSE 差 **−0.000930537**，**[−0.001309387, −0.000500803]**；MAE 由 0.115904742 降到 0.114890631，区间 [−0.001302545, −0.000715313]（不含零）。

**解读**：空间信息在被压缩后确实有损失，补回原始风场有效。这一节点的权重接近一半一半，说明新模型不是"小补丁"，而是实质性互补。

**代价**：特征维度上升；双键匹配要求预报数据完整，缺一个提前量就丢样本。

## 4.4 节点 5：跨站风速时变（−0.22%）

**动机**：上一节点只用了同一时刻的空间切片；风的**变化趋势**（邻站前后几小时怎么变）也是信息。

**做法**：在第一层输入上增加十站 100 米风速在同一预报日内的 `t−3`、`t−1`、`t+1`、`t+3` 值，以及 `t+1 − t−1` 的梯度，共 **50 维**；边界截在该起点 24 小时窗口内，不使用下一批预报。

**权重**：**0.544211283 / 0.455788717**（验证集 43,008 小时）。

**结果**：0.160622327 → **0.160275634**（再降 0.2158%）；MAE 0.114490104。

**区间**：RMSE 差 **−0.000346693**，**[−0.000612461, −0.000093068]**；MAE 差 [−0.000582459, −0.000216244]。

**解读**：时变信息有贡献，但明显小于空间切片（−0.58% vs −0.22%）。边界检查是关键——用错窗口等于用了未来预报。

## 4.5 节点 6：跨站共享模型（−1.68%，单步最大）

**动机**：每站只有约 6,576 小时训练样本，树模型容易欠拟合；十站合并成 65,760 行、加场站类别特征，等于把样本量扩大十倍。

**做法**：保留全部特征，把十站同一 OOF 时间段的样本合并（**65,760 行**），追加 `farm` 类别特征，训练一个共享 LightGBM；固定 `num_leaves=31`、`min_child_samples=80`、最多 800 轮，验证早停选中 **709 轮**。

**权重**：上一最优 **0.587095964** / 共享模型 **0.412904036**。

**结果**：0.160275634 → **0.157582752**（再降 **1.6802%**，是最大的一步）；MAE 0.112679860。

**区间**：RMSE 差 **−0.002692882**，**[−0.004129755, −0.001617600]**；MAE 差 [−0.002510629, −0.001168028]。

**解读**：收益来自"样本量 × 10"，同时保留每站专属模型提供站点个性。注意边界：本轮同时改了训练组织与树容量，证据支持整个配方，不能把收益只归因于合并样本。

**代价**：共享模型对站点差异的处理依赖类别特征；若站点数量继续增长，类别不平衡会出现。

## 4.6 节点 7：场站经验曲线 + 共享残差（−0.17%）

**动机**：功率对风速的响应是单调的，可以用训练期学到的"经验响应曲线"表达站点个性，再让模型只学残差——把一部分规律固化下来，降低模型难度。

**做法**：
1. 每站仅用 2012 训练集，以 100 米预报风速与归一化功率拟合**单调递增的 isotonic 经验曲线**（输出限 0–1，超出训练风速范围取端点）；
2. 共享 LightGBM 在 65,760 行上学习"实际功率 − 曲线值"，并把曲线值作为额外特征；
3. 预测时加回曲线值再裁剪；
4. 验证集确定与上一最优的融合权重。

**权重**：**0.873861511 / 0.126138489**（残差模型只占 12.6%）。

**结果**：0.157582752 → **0.157320468**（再降 0.1664%）；MAE 0.112525922；早停选中 **772 轮**。

**区间**：RMSE 差 **−0.000262284**，**[−0.000429680, −0.000103550]**；MAE 差 [−0.000259440, −0.000045224]。

**解读**：小权重、但区间不含零，属于"细水长流"的一步。曲线提供的是站点个性先验，残差模型提供修正。

**代价**：isotonic 曲线是经验响应，不是厂家功率曲线；风速超出训练范围时只能取端点，极端天气下会偏。

## 4.7 节点 8：标准化 MLP 分支（−0.37%）

**动机**：树模型在特征空间里做分段常数逼近，平滑的神经网络分支可以补上"连续响应"的部分。

**做法**：沿用既有 122 维输入，追加十站固定 one-hot，形成 **132 维**；`StandardScaler` 只在 2012 OOF 的 65,760 行上拟合；MLP 隐藏层 `(128,64)`、ReLU、`alpha=0.1`、批量 512、学习率 0.001、最多 200 轮、种子 42；内部早停用训练期内 15% 随机留出（不碰 2013 标签）。实际训练 80 轮，最佳在第 64 轮。

**权重**：**0.827630628 / 0.172369372**。

**结果**：0.157320468 → **0.156740139**（再降 0.3689%）；MAE 0.111645608。

**区间**：RMSE 差 **−0.000580329**，**[−0.001119223, −0.000046356]**；MAE 差 [−0.001307394, −0.000465185]。

**解读**：神经网络以 17% 权重提供互补；有效的是整个组合，不能据此说"单独 MLP 更强"（单分支明显更弱）。

**代价**：新增一套标准化与训练流程；sklearn MLP 没有嵌入层，站点只能 one-hot。

## 4.8 节点 9（前身，未成立）：MLP 结构网格

**动机**：节点 8 用的是固定结构，也许换结构更好。

**做法**：严格协议下比较 6 个结构：(128,64)/0.1、(256,128)/0.1、(256,128)/1.0、(384,192)/0.03、(128,64,32)/0.1、(64,32)/0.01；全部早停用训练期留出，融合权重只用验证集。

**验证集结果**：最优是 **(128,64,32)/0.1**，验证 MSE 0.0211401（原结构 (128,64)/0.1 为 0.0212540），融合权重 0.1855。

**测试结果**：0.156740139 → **0.156399390**（−0.22%），七日块区间 **[−0.000717, +0.000028] 跨零**，MAE 还升 0.000313。

**判定**：不登记。但这次失败给了一个明确信号：**结构本身不是瓶颈，方差才是**。

## 4.9 节点 9：多种子平均 MLP（−0.47%，当前最优）

**动机**：结构网格证明"换结构"只能带来 −0.22% 且跨零；那么这个分支的波动主要来自初始化，用多种子平均压方差更对症。

**做法**：结构固定为验证集选出的 `(128,64,32)`、`alpha=0.1`；只改一件事——用三个随机种子 **42 / 7 / 2024**，各自以训练期内 15% 留出提前停止（迭代 **122 / 92 / 114**），预测取均值。

**权重**：**0.725116 / 0.274884**；验证 MSE 0.0210285（单结构单种子为 0.0211401）。

**结果**：0.156740139 → **0.156009848**（再降 **0.4659%**）；MAE 0.111269185。

**区间**：RMSE 差 **−0.000730290**，**[−0.001251885, −0.000228719]**（不含零）；MAE 差 [−0.000831237, +0.000096002] **跨零**，不声称 MAE 改善。

**解读**：同结构多种子（−0.47%，区间不含零）明显优于换结构（−0.22%，区间含零）。这是整条链上"方差治理优于容量调整"的直接证据。

**代价**：训练时间 ×3；验证集同时用于结构选择与权重拟合，存在乐观偏差，评价仍是同一历史测试集上的探索性结果。

## 4.10 九个节点的收益递减

| 节点 | 方法 | RMSE | 相对上一节点 | 区间是否含零 |
|---:|---|---:|---:|---|
| 1 | C 基线 | 0.170454204 | — | — |
| 2 | 天气邻域 + OOF 两层 | 0.162180238 | −4.85% | 否 |
| 3 | 验证集凸融合 | 0.161552864 | −0.39% | 否 |
| 4 | 十站原始风场 | 0.160622327 | −0.58% | 否 |
| 5 | 跨站时变 | 0.160275634 | −0.22% | 否 |
| 6 | 跨站共享模型 | 0.157582752 | −1.68% | 否 |
| 7 | 经验曲线残差 | 0.157320468 | −0.17% | 否 |
| 8 | 标准化 MLP | 0.156740139 | −0.37% | 否 |

# 第五章　特征体系：132 维是怎么来的

## 5.1 分层

| 层 | 内容 | 维度 |
|---|---|---:|
| A | 原始 NWP：`u10`、`v10`、`u100`、`v100` | 4 |
| B | A + 派生：`speed10`、`speed100`、风向 sin/cos（10m、100m）、`speed100_cube`、`shear`、小时/年内周期编码、`lead` | 17 |
| C | B + 功率滞后：`lag1`、`lag2`、`lag24`、`mean24`、`std24`、`min24`、`max24`、`trend` | 25 |
| 空间 | 十站同预报时刻 `U100`、`V100`、`speed100` | +30 |
| 时变 | 十站 `speed100` 的 t−3 / t−1 / t+1 / t+3 与梯度 | +50 |
| 站点 | 十站 one-hot（仅 MLP 分支） | +10 |
| 其余 | 天气邻域特征、十站第一层预测（OOF） | 合计 132 的余量 |

## 5.2 三个设计要点

1. **风向用 sin/cos，不用角度**。0° 与 360° 在数值上相邻但语义相同，直接喂角度会让模型在边界处学错；用 sin/cos 编码就没有不连续。
2. **滞后特征只取严格过去**。`lag24` 必须来自 `origin−24` 的真实观测，缺测时整行丢弃，不能"向前找最近的"——那会悄悄引入时间错位。
3. **交叉项留给树模型**。`speed100_cube` 是唯一显式的非线性变换（风的功率 ∝ 风速³），其余组合（如"风速 × 风向"）不手工构造，交给树模型。

## 5.3 为什么后来不再加特征

第 7 章列的失败路线里，有一半是"再加一组特征"：跨站一致性、滚动残差、风向、预报偏差校正、同日上下文、跨站历史功率……全部在验证集门禁折戟。原因在 7.10 统一解释：**十站原始风场已经是这组特征的"展开形式"，树模型能自己组合出均值和离散度，显式聚合只是重复表达。**

# 第六章　融合机制

## 6.1 为什么用凸组合

给定若干模型的预测，融合方式有三种常见选择：

| 方式 | 优点 | 风险 |
|---|---|---|
| 选一个最好的 | 简单 | 丢掉互补性 |
| 线性回归 / stacking | 表达能力强 | 需要额外训练数据；容易过拟合验证集 |
| **凸组合（非负、和为一）** | 参数少（k−1 个自由度）、外推安全、可解释 | 表达受限 |

我们的选择是凸组合，理由：

1. **参数极少**：三模型只有 2 个自由度，43,008 个验证小时足够稳；
2. **外推安全**：权重非负、和为 1，融合值永远在候选模型值之间，不会出现"权重为负导致外推爆炸"；
3. **可审计**：每个权重都能解释成"这个模型的贡献占比"。

## 6.2 权重演变

| 节点 | 新组件权重 | 上一最优权重 | 验证集 MSE |
|---|---:|---:|---|
| 3（三模型） | 完整两层 0.7934；邻域 0.0843；C 0.1223 | — | — |
| 4（空间风场） | 0.453502164 | 0.546497836 | — |
| 5（跨站时变） | 0.455788717 | 0.544211283 | — |
| 6（共享模型） | 0.412904036 | 0.587095964 | — |
| 7（曲线残差） | 0.126138489 | 0.873861511 | — |
| 8（MLP） | 0.172369372 | 0.827630628 | — |
| 9（种子平均 MLP） | 0.274884 | 0.725116 | 0.0210285 |

两条观察：

- **权重与增益不成正比**。节点 7 的新组件只占 12.6%，但它的区间不含零；节点 4 占 45%，增益也只有 0.58%。权重反映"互补程度"，不反映"绝对强弱"。
- **同一验证集既选结构又定权重，会放大乐观偏差**。节点 9 的结构与权重都来自验证集，所以它的 −0.47% 里有一部分是拟合出来的。这一点在解读里必须写明。

## 6.3 为什么不是 meta-learner

曾想用 LightGBM 把"各组件预测 + 工况特征"映射到最终功率，替代固定凸组合。两步都失败了：

**第一步（设计越界，已中止）**：脚本直接在 2013 上半年验证集上做 5 折时间块 CV 选轮数、再全量重拟合——等于把验证期标签用于训练。运行在数据准备阶段因列名不匹配报错中止，没有产生指标。这属于协议事故（第八章）。

**第二步（合法但机制不成立）**：改用 2012 期内时间顺序 OOF 做可行性检查（3 折、65,760 行、固定轮数、不碰验证/测试）：

| 方案 | 期内 OOF 误差 |
|---|---:|
| 固定凸融合 | **0.155390** |
| meta-learner（LightGBM） | 0.162994 |

**三折全负，合并 +4.9%**。原因不是分布迁移（见 9.3 的分布对照），而是**过拟合**：65,760 行上，一个能看全部组件预测的模型很容易学到"哪折的哪段组件碰巧更准"，而这在测试期不复现。

结论：**机制不成立**，不是"试过没用"。不要再回头。

# 第七章　被否路线全表与逐条诊断

## 7.1 判定标准

一条路线被否，必须满足下面**至少一条**，并在档案里写清是哪一条：

| 判定 | 含义 | 证据形式 |
|---|---|---|
| 区间含零 | 七日块配对 95% 区间跨零 | `paired.json` |
| 方向为负 | 点估计变差 | `metrics.csv` |
| 未过幅度门 | 验证集区间上界 > −0.0002 | `validation_gate.json` |
| 组件本身更差 | 融合改善但被融合的组件单独更差 | 段内/分支指标 |
| 协议不允许 | 用验证集标签训练 | `protocol.json` 自述 |

## 7.2 融合层面

| 轮次 | 改动 | 测试 ΔRMSE | 区间 | 判定 |
|---|---|---:|---|---|
| `site_blend_v1` | 按场站拟合融合权重 | +0.000277 | [+0.000022, +0.000527] | 方向为负，且区间不含零（说明**真的更差**） |
| `lead_blend_v1` | 按提前量拟合权重 | +0.000177 | [+0.000039, +0.000322] | 同上 |
| `joint_blend_v1` | 联合重估全部权重 | +0.000055 | [−0.000093, +0.000224] | 区间含零 |
| `mean_stack_shared_v1` | 均值堆叠 | 未评分 | — | 验证集直接给 0 权重，门禁即弃 |
| `prediction_calibration_v1` | 预测校准 | +0.000090 | [−0.000224, +0.000382] | 区间含零 |

**诊断**：按场站/按提前量拆权重，本质是把 43,008 个验证小时切成 10 份或 3 份，每份只剩 4,300 / 14,336 小时——参数多了、样本少了，**权重拟合误差盖过了个性化收益**，甚至稳定变差（前两条区间不含零）。

| `extra_trees_v1` | ExtraTrees 分支 | +0.000001 | [−0.000064, +0.000069] | 基本持平 |
| `shared_capacity_search_v1` | 共享模型容量搜索 | −0.000081 | [−0.000232, +0.000032] | 区间含零 |
| `shared_median_v1` | 中位数聚合 | −0.000080 | [−0.000212, +0.000047] | 区间含零 |

**诊断**：
- **多样性/换学习器基本无效**：核岭、HistGradient、ExtraTrees 与现有树模型的误差高度相关，互补信息接近零。
- **方差治理用错了对象**：LightGBM 在 65,760 行上本身稳定，子采样 + 5 种子只是丢数据（+0.000081）；而 MLP 的方差来自初始化，所以种子平均有效（−0.47%）。
- **两段式失败有明确原因**：RMSE 的最优点就是条件均值，把"是否静风"拆开分别估计，再按概率合成，反而引入估计误差；单棵 L2 树已经学到了边界。
- **池化基础分支失败说明"信息已被吃掉"**：早期池化有效，是因为链里还没有共享模型；现在共享分支已占 26%，再池化一次是冗余。

| `direction_shared_v1` | 风向特征 | −0.000013（测试） | [−0.000040, +0.000009] | 区间含零 |
| `forecast_bias_shared_v1` | 预报偏差校正 | −0.000021（测试） | [−0.000078, +0.000032] | 区间含零 |
| `dispersion_features_v1` | 跨站一致性/离散度 | −0.000074（验证） | [−0.000215, +0.000064] | 未过幅度门 |
| `rolling_residual_features_v1` | 滚动 OOF 残差 | −0.000138（验证） | [−0.000347, +0.000072] | 未过幅度门；打乱对照无差异 |

**诊断**：这些特征的信息**已经被十站原始风场与其他站预测覆盖**。举个具体例子：十站 `speed100` 的均值，是这 10 列的线性组合，树模型只要在 10 列上做几次分裂就能表达；显式算一个"均值列"不会增加信息，只会增加一列噪声。

`rolling_residual_features_v1` 还多了一层证据：把 30 天块顺序随机置换后重训，结果只差 2.7e-6——说明模型几乎没用这组特征，既没泄漏，也没时间信息。

## 7.5 表征与结构层面

| 轮次 | 改动 | 结果 | 判定 |
|---|---|---|---|
| `mlp_tuned_v1` | 6 个结构网格（单种子） | 验证最优 (128,64,32)；测试 −0.000341，[−0.000717, +0.000028] | 区间含零 |
| `lead_segments_v1` | 按提前量 1–8 / 9–16 / 17–24 分段建模 | 验证 −0.000444 [−0.000694, −0.000203]；测试 −0.0000132 [−0.000457, +0.000464] | 测试区间含零，不成立 |
| `mlp_seed8_check_v1` | 种子 3 → 8 | 验证 −0.000266 [−0.000551, +0.000028] | 未过幅度门 |

**`lead_segments_v1` 是整条链上最有教育意义的一次失败**，值得单独展开（7.6）。

**种子 3 → 8** 的读数是：3 种子已拿到 −0.47%，扩到 8 种子只再降不到 0.02%，且区间跨零——种子平均的边际收益在 3 个附近就耗尽了。

## 7.6 案例研究：验证集通过、测试不成立

提前量分段这轮的完整数据：

| 段 | 验证集小时 | 训练行 | 段内验证 RMSE（现行最优） | 分段组件单独 | 融合后 |
|---|---:|---:|---:|---:|---:|
| 1–8 | 14,336 | 21,920 | 0.127780 | 0.133266 | 0.127517 |
| 9–16 | 14,336 | 21,920 | 0.156232 | 0.159484 | 0.155712 |
| 17–24 | 14,336 | 21,920 | 0.149498 | 0.153975 | 0.148972 |

三段的样本量**完全相等**（排除了"某段样本少导致不稳"的解释），但**分段组件在三段里单独都更差**（差 0.004–0.005）。

那么验证集那 −0.000444 从哪来？来自融合权重：把更差的组件以较小权重混进去，恰好在那 43,008 个小时上凑出了小幅改善。这不是"分段建模有效"，而是"权重拟合的乐观偏差"。

测试集评一次：−0.0000132，区间 [−0.000457, +0.000464] 跨零，MAE 还升 0.000262。**不登记，不重试。**

**可复用的判断规则**：如果验证集改善但被融合的组件单独更差，先怀疑权重拟合，不要急着开测试集。

|---|---|---|
| `expanded_refit_v1` | −0.000701，区间 [−0.001647, +0.000223] | 区间含零，且把验证集标签用于训练，**协议不允许** |
| 三个 `*_final_refit_v1` | 0.156327568 / 0.155737496 / 0.155443654 | 同上，全部作废（第八章） |

## 7.8 失败模式归纳

把 30+ 条被否路线按"为什么失败"归类，只有五类：

| 类型 | 典型代表 | 识别特征 | 应对 |
|---|---|---|---|
| 噪声量级 | 大多数 < 1e-4 的改动 | 点估计正、区间跨零 | 直接放弃，不调参重试 |
| 重复信息 | 一致性、离散度、风向、跨站历史 | 输入里已有等价展开 | 问"这组量能不能由现有列线性组合得到" |
| 验证集拟合偏差 | 按站/按提前量权重、分段建模 | 组件本身更差但融合更好 | 看组件单独成绩，再决定是否开测试集 |
| 方差来源误判 | LightGBM 子采样 + 5 种子 | 学习器本身稳定还被"治理" | 先测方差来源（种子 / 数据 / 特征） |
| 协议不允许 | 重拟合、验证集 meta-learner | protocol 里出现 2013 标签 | 作废，不复活 |

## 7.9 为什么"再加特征"这条路整体走不通

第 4–6 章已经说明，链上已有：

- 十站同一时刻的原始 `U100/V100/speed100`（30 维）；
- 十站前后几小时的 `speed100`（50 维）；
- 十站第一层预测（OOF）；
- 每站的经验功率曲线与共享残差模型。

在这样的输入下，任何"跨站统计量"都是这些列的确定函数。树模型在每个节点选一个特征做阈值分裂，等价于在学这些列的组合；显式给出均值/标准差，只是把"组合"提前算好——对**树**几乎无增益，对**线性模型**才有意义。

这条推理直接给出了停止规则：**当候选特征可以由现有列（近似）线性组合得到时，不要开实验。**

## 7.10 一条反例：为什么"验证集有效"不能直接外推

`lead_segments_v1` 的验证集区间不含零（[−0.000694, −0.000203]），按当时的门槛（只要不含零）就该开测试集；但测试结果是 −0.0000132。这说明：

- 验证集的 43,008 小时与测试集的 42,432 小时**不是同一分布**（2013 上半年 vs 下半年，季节不同）；
- 权重在小样本上拟合出的改善，可能只是那半年的局部结构；
- 因此"验证集通过"只是必要条件，不是充分条件。

2026-11-14 晚把门槛收紧到"上界 ≤ −0.0002"，就是为了让这类贴线通过不再消耗测试集。

# 第八章　越界与作废：两次协议事故

## 8.1 三个"最终重拟合"节点

早期为了让最终模型更强，做过三次"把 2013 上半年验证期标签并入最终拟合"：

| 节点 | 曾得到的 RMSE | 作废原因 |
|---|---:|---|
| 共享分支最终重拟合 | 0.156327568 | 验证集标签进入训练 |
| MLP 分支最终重拟合 | 0.155737496 | 同上 |
| 时变分支最终重拟合 | 0.155443654 | 同上 |

2026-11-14 用户明确"只用 2012 训练"后，三个节点从注册表、进展图、文档中移除；证据留在 `artifacts/.../{shared,mlp,temporal}_final_refit_v1/` 仅供核对，**不得复活，也不与新节点比较**。

为什么它们看起来"更好"：验证期与测试期相邻，季节与天气过程更接近；把验证期标签给模型看，等于让它提前适应了测试期的分布。这不是模型能力，是数据泄漏。

## 8.2 meta-learner 的两次尝试

**第一次（设计越界，已中止）**：脚本直接在验证集上做 5 折时间块 CV 选轮数、再全量重拟合，`protocol.json` 里自己写着 "Meta-learner training set is the 2013 H1 validation"。运行在数据准备阶段因列名不匹配报错中止，没有产生任何指标；空目录已删，脚本未跟踪。这类做法与 8.1 同性质，属"验证集标签进训练"。

**第二次（合法但机制不成立）**：改用 2012 期内时间顺序 OOF 作为训练输入（三折、65,760 行、固定轮数、不碰验证/测试）。结果：固定凸融合 0.155390，meta-learner 0.162994，三折全负，合并 +4.9%。

结论分两层写，避免混淆：

- **设计层面**：第一次是协议事故，已中止、无指标；
- **机制层面**：第二次是合法实验，证明"用模型替代凸组合"在这套数据结构上不成立（过拟合，不是分布迁移）。

## 8.3 作废流程

1. 从 `optimization-progress.json` 移除节点；
2. 重跑 `plot_optimization_progress.py` 重画图；
3. 文档里的表格与叙述同步删除或标注；
4. 证据目录保留，不删除，供核对；
5. 在 tricks/饱和评估里记一条"不得复活"。

# 第九章　饱和证据

## 9.1 证据一：最近四轮的效应量

| 轮次 | 验证集 ΔRMSE | 区间 | 判定 |
|---|---:|---|---|
| MLP 种子 3→8 | −0.000266 | [−0.000551, +0.000028] | 跨零，未过 −0.0002 |
| 滚动 OOF 残差 | −0.000138 | [−0.000347, +0.000072] | 跨零；打乱对照仅差 2.7e-6 |
| 提前量分段 | −0.000444（测试 −0.0000132） | 测试 [−0.000457, +0.000464] | 跨零 |
| 跨站一致性 | −0.000074 | [−0.000215, +0.000064] | 跨零 |

四轮的效应量都在 **1e-4 量级或更低**，且**没有一轮成立**。

## 9.2 证据二：噪声地板

七日块配对区间的半宽约 **2e-4**。这意味着：

- 任何真实效应小于 2e-4 的改动，即使方向正确，也无法被这个设计证明；
- 而最近四轮的全部候选都在 3e-5～3e-4 之间——正好卡在噪声地板上。

要证明更小的效应，只有两条路：换更细的配对设计（会引入新的假设），或者扩大测试期（不可能，历史数据就这么多）。

## 9.3 证据三：余量测算

把现行最优在测试集上的十个分站偏差（−0.0102 ～ +0.0150）**全部抹平**——这是任何"站点表征改进"理论上的最好情况：

| 项 | 数值 |
|---|---:|
| 抹平前 RMSE | 0.156010 |
| 抹平后 RMSE | 0.155691 |
| 上限改善 | **−0.000319** |
| MLP 分支在链中权重 | 27.5% |
| 折算到链上 | **≤ −8.6e-5** |
| 其他分站分支已吸收部分偏置后的实际预期 | **≤ 5e-5** |

而开测试集的门槛是 −0.0002。**即使机制完全按预期工作，也过不了门。** 同一算术适用于所有"换表征/换超参"的候选：one-hot 换嵌入、加深度、换激活、加残差连接——可解释的修正量级都小于"链上权重 × 分站偏置上限"。

## 9.4 副产品：分布对照纠正了一个错误假设

做 meta-learner 可行性检查时，顺手对比了三段数据的组件预测分布（均值）：

| 数据段 | 组件预测均值 | 标准差 |
|---|---|---|
| 2012 期内 OOF | 约 0.345–0.358 | 0.27–0.29 |
| 2013 上半年验证 | 约 0.295–0.305 | 0.27–0.29 |
| 2013 下半年测试 | 约 0.413–0.424 | 0.27–0.29 |

**形状几乎一样，只有水平位移。** 而且 OOF 的水平比验证集**更接近测试期**。所以"期内学到的组合规律迁移到测试期会因分布迁移失真"这个担心方向是错的；meta-learner 三折全负的真正原因是**过拟合**，不是迁移。

这条结论有复用价值：以后再用期内 OOF 做方法验证，不必把水平偏移当主要风险，应把注意力放在容量与交叉折设计上。

## 9.5 证据四：信息面已用尽

| 信息 | 有没有 | 用没用 |
|---|---|---|
| `U10/V10/U100/V100` | 有 | 全部用上（含派生） |
| 十站空间与时间邻域 | 有（同数据集） | 已用（节点 4、5） |
| 温度、气压 | 无 | — |
| 机组布局、轮毂高度 | 无 | — |
| 限电/弃风标记 | 无 | — |
| 站点坐标（接再分析数据） | 无（匿名站） | 已关闭该路线 |

## 9.6 三条证据合起来

1. 效应量已经掉到噪声地板上（9.1、9.2）；
2. 即使理论最优也过不了门槛（9.3）；
3. 没有新信息可加（9.5）。

**结论：这条链在现有信息源上饱和。** 继续在旧信息上换表征/换超参，属于钓鱼。

# 第十章　经验教训

每条都附证据，避免变成格言。

1. **先建评估协议，再谈优化。** 前 10 个节点用掉 11 次测试集，后半程几乎不敢开——如果一开始就有"门禁 + 台账"，测试集不会这么紧张。

2. **最大的一步来自加信息，不是调模型。** 邻域 + 两层一次 −4.85%，而 6 个 MLP 结构网格只有 −0.22% 且跨零。

3. **样本量比容量更值钱。** 十站合并（65,760 行）带来 −1.68%，是单步最大之一；而容量搜索是 −0.008%。

4. **方差治理要看方差来源。** MLP 种子平均 −0.47%（区间不含零）；LightGBM 子采样 + 5 种子 +0.008%（方向变差）。同一个"技巧"，换个学习器就反效果。

5. **验证集拟合权重会掩盖较差组件。** 提前量分段：验证 −0.000444，但三段组件单独都更差，测试只有 −0.0000132。

6. **target encoding / 残差特征必须做打乱对照。** 滚动残差特征点估计 −0.000138 看着还行，打乱块顺序后只差 2.7e-6——证明模型根本没在用。

7. **融合权重先冻结，再开测试集。** 所有节点都遵循这条；这也是"权重不是从测试集选的"唯一可信证明。

8. **给自己设停止规则。** 连续两轮不过门禁就停，不再换表征/超参。这条规则省下的不是算力，是测试集。

9. **区间宽度决定你能证明多小的效应。** 半宽 2e-4 意味着 1e-4 的改进不可证；不要用点估计自我安慰。

10. **分布迁移不是主要风险，过拟合才是。** 三段分布形状一致、水平位移；meta-learner 失败的原因是 65,760 行上过拟合。

11. **作废节点保留证据，但永不复活。** 三个重拟合节点的数字更漂亮，但它们是泄漏的产物；一旦允许复活，整条链的可信度就没了。

12. **"整体方案有效"不等于"每个组件都有效"。** 多数节点的证据支持的是"特征 + 融合"的整体配方，不能拆开归因；文档里每次都要写这句边界。
