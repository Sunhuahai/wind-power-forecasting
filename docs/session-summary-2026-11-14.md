## 二、本轮做了什么

1. **接手与体检**：确认 PostgreSQL 18.7 在 55432 可用、十站数据完整；`pytest` 35 passed / 1 skipped。修好了反复失效的虚拟环境——`.venv` 从会被 macOS 清理的 `/private/tmp` 迁到 `~/.local/share/windpower-venv`，并写进 README。
2. **协议纠偏**：把三个"把 2013 上半年标签并入训练"的最终重拟合节点（0.156327568 / 0.155737496 / 0.155443654）**永久作废**，注册表、图表、文档同步移除；严格协议基线回到第 7 节点 0.156740139。
3. **新的成功节点（第 9 个）**：验证集从 6 个结构里选出 `(128,64,32)`，再用 **3 个种子（42/7/2024）平均**替换 MLP 分支。单种子版只到 0.156399 且区间跨零（记失败），种子平均后 **0.156740139 → 0.156009848（−0.4659%）**，七日块配对 95% 区间 **[−0.001252, −0.000229]**。结论：该分支的瓶颈是初始化方差，不是结构。
4. **被否的 8 轮**（详见下表）与 1 轮越界（meta-learner 用验证集训练，未按协议执行，只做期内 OOF 可行性后封路）。
5. **进展图重做**：阶梯线 + 轮次横轴 + 斜排标签 + 灰色被否候选点；中文字体用系统 Arial Unicode，PDF/SVG 正常嵌入。
6. **饱和评估与仓库整理**：新增饱和评估文档、文档索引；证据策略统一为"所有轮次保留小型 protocol/metrics/paired/decision 证据，模型与逐小时预测不进库"；跟踪体积从 69MB 降到 17MB。

## 四、可复用经验

1. **降方差只对高方差学习器有效**：MLP 初始化方差大，种子平均 −0.47%；LightGBM 在 6.5 万行上几乎确定，子采样只有损失。
2. **池化只需做一次**：第 5 节点靠池化拿 −1.68%，之后再池化其他分支就是冗余。
3. **RMSE 的最优点始终是条件均值**：拆点质量、两段式、校准都改变不了这一点。
4. **验证集拟合的权重会掩盖较差的组件**：提前量分段时组件自己三段都更差，但融合在验证集上"改善"，到测试集就消失。判断要看组件本身，不要只看融合结果。
5. **target-encoding 类特征必须做时间顺序对照**：把块顺序打乱重训，如果成绩不变，说明特征没有携带时间信息（本轮正是如此）。
6. **门禁要留幅度**：验证集区间贴着零就开测试集，等于白烧一次评分；现在规则是区间上界 ≤ −0.0002 才允许开。

## 五、协议红线（务必保持）

- 训练：**只允许 2012 全年**；2013 上半年只能做早停、选结构、拟合凸融合权重；2013 下半年只评分一次。
- **验证集标签不得进入任何训练或重拟合**，meta-learner 也算。
- 每个实验目录的 `protocol.json` 必须显式写明：训练数据、早停数据、权重数据、评分数据。
- 失败只进 `optimization-tricks`，不进进展图；只有 RMSE 前进且七日块配对区间不含零才登记。

## 六、下一步：需要新数据

GEFCom2014 风电只有 `U10/V10/U100/V100` + 功率，十个 ZONEID 是匿名站（没有经纬度、容量、机组布局），所以外部再分析数据无法对位接入。若要继续优化，需要提供：

1. **必需键**：`ZONEID`(1–10) + `TIMESTAMP`（与现有数据同时钟、无时区）。
2. **建议内容**：限电/弃风标记、可用容量、检修记录（价值最高——现在的模型把限电当成预报误差在学）；或温度/气压（算空气密度）、轮毂高度/布局（算尾流）。
3. **覆盖**：最好 2012 + 2013 全年；放在项目 `data/external/` 下。

或者提供**十个站的经纬度映射**，就可以去取公开再分析数据。

**2026-11-15 结论**：十个 ZONEID 是匿名站，官方无经纬度，用户也没有坐标映射，外部再分析路线**关闭**；取数管线（`configs/sites.json` + `scripts/fetch_reanalysis.py`）保留待命，拿到坐标即可重启。优化阶段正式收尾在 **0.156009848**。
