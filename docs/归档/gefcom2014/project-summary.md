# 风电功率预测项目 · 到目前为止做了什么

更新：2026-11-15

## 一句话

用 GEFCom2014 的十站风电数据，从原始官方文件搭起一条可复现的预测流水线，把十站合并测试误差（RMSE）从 **0.1705 降到 0.1560**，降幅 **8.47%**，并且把每一步的证据、失败原因和评估规则都固定下来；现在正在为"接真实数据做实时预测"做准备。

## 一、起点：先把地基打好

- 下载并解析官方数据（十个场站、每站两年的小时级功率 + 四种天气预报分量）。
- 全部导入 PostgreSQL，建立站点、观测、预报、划分、模型、预测六张表。
- 按固定划分切分：**训练 2012 年、验证 2013 上半年、测试 2013 下半年**（这条线一直没动）。
- 做了三类基线模型对比：简单持续法、岭回归、LightGBM 三种特征组合。
- 结果：LightGBM 用"天气预报 + 物理特征 + 历史功率"的组合最好，十站合并 **RMSE 0.1705**（持续法是 0.3489）。

## 二、优化：9 个有效节点，0.1705 → 0.1560

| 节点 | 做了什么（一句话） | RMSE |
|---|---|---:|
| 0 | 基线：天气预报 + 物理特征 + 历史功率 | 0.1705 |
| 1 | 加入邻站天气和"跨站预测"两层结构 | 0.1622 |
| 2 | 用验证集把几个模型凸组合起来 | 0.1616 |
| 3 | 再加入十站的原始风场数据 | 0.1606 |
| 4 | 加入邻站风速随时间的变化 | 0.1603 |
| 5 | 十站合并训练一个共享模型（收益最大的一步） | 0.1576 |
| 6 | 加入场站经验功率曲线 + 残差模型 | 0.1573 |
| 7 | 加一个神经网络（MLP）作为补充 | 0.1567 |
| 8 | 用验证集选网络结构 + 多个随机种子平均 | **0.1560** |

一句话概括方法：**不断给模型补充"别的场站、别的时刻"的信息，再用验证集决定各模型占多少权重。**

### 改进最大的三个，展开说

**第 1 名：让模型知道"邻居怎么吹"（节点 1，−4.85%，0.1705 → 0.1622）**

- 原来：每个场站只看自己的天气预报和过去的功率，等于十个互不通信的模型。
- 做法：改成两层。第一层每站先各自预测一次；第二层把十站第一层的预测当作输入，再预测一次；同时补进同一预测日内附近场站的"风能邻域"特征。
- 最容易出错的地方：第二层的训练输入必须是**时间顺序的样本外预测**（用当天之前的数据训练出的模型去预测当天），否则等于偷看答案，指标会虚高。
- 结果：RMSE 降 4.85%，MAE 从 0.1235 降到 0.1160。分组对照显示：只加邻站天气值 −0.0047，再加跨站预测 −0.0049，两个区间都不含零。
- 为什么有效：同一片天气系统会同时影响多个场站，单站模型看不到这层关系。
- 代价：模型数量从几个变成二十多个，训练与部署复杂度明显上升。

**第 2 名：十站合并训练一个共享模型（节点 5，−1.68%，0.1603 → 0.1576）**

- 原来：每站各一个模型，每站只有约 6,600 小时样本，学得比较虚。
- 做法：把十站样本合并成 65,760 小时，加一个"场站编号"特征，训练一个共享模型；再按验证集定出的比例（0.587 / 0.413）与原来的分站模型组合。
- 结果：RMSE 降 1.68%，区间 [−0.00413, −0.00162]，是单步收益第二大的一步。
- 为什么有效：样本量扩大十倍，模型学到的规律更稳；同时保留分站模型，避免把站点个性抹平。
- 代价：不再是"一站一个模型"，可解释性和上线部署都更复杂。

**第 3 名：直接把十站的原始风场喂进去（节点 3，−0.58%，0.1616 → 0.1606）**

- 原来：跨站信息只有第一层的预测值，而预测值已经把原始信息压缩过一遍。
- 做法：把十站同一时刻的 U100/V100/风速**原样**作为特征加进第二层，按"预测起点 + 目标时刻"双键匹配；只用预报字段，不碰目标功率。
- 结果：RMSE 降 0.58%，区间 [−0.00131, −0.00050]；MAE 从 0.1159 降到 0.1149。
- 为什么有效：压缩过的预测丢掉了细节，原始风场保留了邻站的风速量级与方向。
- 代价：特征维度加 30 维，训练更慢。

> 参考：第 4 名是最近那步"验证集选网络结构 + 多种子平均"（−0.47%）。从这里能看出，越往后单步收益越小——前面几步是"加信息"，后面几步基本是"压噪声"。

## 三、试过但没用的（这些弯路不用再走）

- 按场站、按提前量给不同权重 → 更差
- 树模型换容量、加随机性、多种子 → 没变化
- 把静风单独拆成两段建模 → 没改善
- 再合并一次十站模型 → 重复了，没信息
- 用验证集学一个"动态加权"的模型 → 过拟合，明显更差
- 按提前量分段训练 → 三段单独都更差
- 加"风场一致性"特征、加"历史误差"特征 → 都在噪声量级

结论：**在现有数据里能挖的信息基本挖完了**。剩下的提升需要新数据（温度、气压、限电记录等）。

## 四、过程中纠正过的两个错误（重要）

1. **作废了 3 个"重拟合"节点**：那几轮为了涨分，把验证集（2013 上半年）的标签也拿去训练了。这违反了你定的规则，已从图表和记录里全部移除，现在所有节点都严格只用 2012 年训练。
2. **拦下一个越界实验**：曾想让一个模型直接在验证集上学习怎么组合，等于拿验证集当训练集，发现后中止、只留了违规记录，没有产生任何指标。

## 五、为了以后能信这些数字，定下的规则

- 训练只用 2012；验证集只做三件事（早停、选结构、定权重）；测试集只评一次。
- 只有误差真的下降、且统计区间不含零，才算一个成功节点。
- 开测试集还有更严的门槛：验证集上必须**明显**更好（区间上界 ≤ −0.0002）才允许，避免浪费评分次数。
- 每个实验都留一份 `protocol.json`，写明"哪些数据用来训练、哪些用来选择、哪些只用来评分"。

## 六、为实时预测做的准备（进行中）

- 把现在这套最优模型打包成**带版本号的模型包**（`models/wind_v1`），换模型不用改推理代码。
- 数据库新增"预报修订批次"表，支持真实业务里预报会更新、会迟到的情况。
- 写好了准备文档：接口怎么定、分几步上线、有哪些风险（最大风险是**限电**——真实数据里低功率往往是人为限电，不是风小）。
- 还差你的真实数据格式（NWP 来源、发布与到达时间、观测频率、站点容量与时区、出预报的时间要求）。
