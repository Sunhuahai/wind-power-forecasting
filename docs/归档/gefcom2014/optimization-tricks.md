## 已验证：天气邻域 + 时间顺序 OOF 跨站两层模型（整体方案）

- 同样 42,432 个测试小时，冻结 C 的 RMSE 0.170454204 → 0.162180238（降低 4.8541%），MAE 0.123454374 → 0.115982666（降低 6.0522%）。十站中八站 RMSE 降低，Zone 2、8 上升。

- 2026-11-14 重新下载成功工作流的指标，并由逐站样本数加权平方误差重算合并 RMSE，与 summary.json 一致至 1e-12。
- [运行证据](https://github.com/Sunhuahai/wind-power-forecasting/actions/runs/42624048464)，下载 artifact 名 `kpower-replay-results`；详细逐站结果见 [[kpower-reproduction-results]]。
- 边界：这是整体方案效果，尚不能归因于单独的邻域或跨站特征；不是冠军源码或原比赛分数。已有测试集已用于报告，后续结果应标为同一历史基准上的探索性评价，不能当作全新盲测。

## 已验证的新 trick：验证集全站共享凸融合

固定候选为以上 C、neighbors、full 三组预测，仅最小化合并验证 MSE；全站共享三个非负权重，和为一。权重文件写入后才加载测试预测，禁止测试集选择权重。验证集已用于各基模型早停，故不能把该验证误差视为独立泛化误差。测试评价仍为探索性的历史基准。

```sh
python scripts/run_validation_blend.py --ablation-id ablation_20261114_v1
```

2026-11-14 已完成：43,008 个验证小时拟合出的权重为 **C 0.122281198、neighbors 0.084286243、full 0.793432559**。权重先写入文件，然后加载测试集。

|方案|测试 MAE|测试 RMSE|
|---|---:|---:|
|完整两层|0.115982666|0.162180238|
|验证集凸融合|0.115904742|**0.161552864**|

相对完整两层 RMSE 再降低 **0.3868%**；相对最初冻结 C 降低约 **5.22%**。融合−完整两层 RMSE 差 -0.000627374，2000 次七日连续日历块配对 95% 区间 **[-0.000963197, -0.000286049]**。MAE 差 -0.000077924，区间 [-0.000326755, 0.000176262]，尚不能声称 MAE 稳定改善。

实用要点：保留有差异但单独较弱的模型，使用验证集确定凸融合权重，可能降低最强单模型的误差；本次只试这个预先固定的全站共享方案，未按测试集搜索权重。区间仅反映固定模型在当前历史测试期的日块不确定性，不包括重新训练和新年份。

## 未通过：两段式（静风门槛）共享模型

诊断显示测试小时里 8.7% 的实际功率 <0.005（其中 2,813 个小时精确为 0），低功率段误差占 MSE 的 22.9%。因此把 26% 权重的共享分支换成两段式：LightGBM 二分类判断“是否接近静风”（阈值 0.005），另一个 LightGBM 只在非静风样本上回归，条件均值按 `P(发电)·E[Y|发电] + P(静风)·mean(静风样本)` 组合，两段都用验证集早停。

测试 RMSE 0.156009848 → 0.156201079（+0.000191），七日块区间 **[-0.0000183, +0.00070]** 跨零。**不登记。**

证据：`artifacts/kpower_ablation/ablation_20261114_v1/hurdle_shared_v1/`。可复用要点：RMSE 的最优点仍是条件均值，把点质量拆开估计并不会自动降低平方误差——单棵 L2 树已经把边界信息学到了。

## 设计越界：验证集训练的 meta-learner（未按协议执行，不计为实验）

曾想用 LightGBM 把各组件预测 + 工况特征（提前量、场站、小时、风速、跨站风速离散度）映射到最终功率，以替代固定凸组合。脚本把该模型直接拟合在 2013 上半年验证集上：先在验证集内部做 5 折时间块 CV 选轮数，再在全部验证行上重拟合，protocol 里也自述 "Meta-learner training set is the 2013 H1 validation"。

这等于把验证期标签用于训练一个模型，超出"验证集只用于早停、选结构与拟合融合权重"的边界，与已作废的三个重拟合节点同类。运行在数据准备阶段因列名不匹配报错中止，**没有产生任何指标、没有登记、没有进图、没有提交**；空目录已删除，脚本 `scripts/run_meta_learner.py` 保持未跟踪。

合法替代（需先确认）：用 2012 训练期内部的时间顺序 OOF 预测作为 meta-learner 的训练输入，验证集只做早停与健全性检查，测试集最后只评一次。注意 2012 OOF 预测本身来自训练期，不存在标签泄漏，但 meta-learner 的容量必须由验证集之外的信号约束，否则仍会在这个 43,008 行的样本上过拟合。

## 边界说明：OOF 与验证集/测试期的分布关系（meta-learner 结论的副产品）

第一段的分布对照（组件预测均值）：2012 期 OOF 约 0.345–0.358，2013 上半年验证集约 0.295–0.305，2013 下半年测试集约 0.413–0.424；标准差三段接近（0.27–0.29），差异主要是水平偏移而非形状变化。分功率五档看是同一模式。

因此"2012 期内的组合规律迁移到测试期会因分布迁移而失真"这个担心方向是错的：**OOF 的水平比验证集更接近测试期**。meta-learner 在第一段全负，原因是它在 65,760 行上过拟合，不是分布迁移。以后再用期内 OOF 做方法验证，不必把"水平偏移"当作主要风险，应把注意力放在模型容量与交叉折设计上。

## 未通过：滚动 OOF 残差特征（含时间顺序打乱对照）

做法：按 30 天分块，对每个场站、每个提前量段（1–8 / 9–16 / 17–24）统计**严格早于当前块**的前两块残差（第一层 OOF 预测误差）的均值、绝对均值、标准差，共 5 个特征；训练仍只用 2012，验证/测试行使用 2012 最后一个块冻结的统计量，不碰验证与测试期残差。

**结果**

| 方案 | 验证集 RMSE | 相对现行最优 | 七日块 95% 区间 |
|---|---:|---:|---|
| 现行最优 | 0.145012 | — | — |
| 真实时间顺序特征 | 0.144874 | −0.000138 | [−0.000347, +0.000072] |
| **打乱块顺序对照** | **0.144871** | −0.000141 | — |

真实顺序与打乱顺序几乎完全一样（差 2.7e-6），说明这组特征**既没有泄漏、也没有带来时间信息**：模型基本没在用它们。加上区间跨零且未达 −0.0002 的新门禁，**测试集未打开**。

**设计弱点**（下次若再碰）2012 只有 9 个 30 天块，每个场站每段只有 9 个不同取值，分辨率太低；若要重做应改用 7 天块（27 个取值）并同时检验块长敏感性。
